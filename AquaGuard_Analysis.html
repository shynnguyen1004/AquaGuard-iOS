4. Đánh Giá Code & Các Vấn Đề

✅ Điểm tốt

  • MVVM rõ ràng: View và ViewModel tách biệt, sử dụng @StateObject / @ObservedObject đúng cách
  • Firebase integration chuyên nghiệp: Real-time listener cho flood zones, image upload flow tốt
  • Design System nhất quán: Color extensions (aquaPrimary, aquaNavy...) hỗ trợ Dark Mode
  • Reusable components: QuickActionButton, StatusCard, ResourceCard, SafetySection được tách thành struct riêng
  • Location permission handling đầy đủ các case

🔴 Vấn đề nghiêm trọng

1. Trùng lặp CLLocationManager ❌

Cả MapViewModel và ReportViewModel đều tạo riêng một CLLocationManager: 

// MapViewModel.swift (line 21)
  private let locationManager = CLLocationManager()

// ReportViewModel.swift (line 31)
  private let locationManager = CLLocationManager()

Cả 2 đều có logic xin quyền, setup delegate, xử lý authorization — copy-paste gần như y hệt. Nên tạo một LocationService dùng chung.

2. Xung đột tên Alert ❌

Struct Alert trong Models.swift (line 60) trùng tên với SwiftUI.Alert. Bạn đã phải dùng SwiftUI.Alert(...) tại LoginView.swift:65 để tránh conflict. Nên đổi tên thành FloodAlert hoặc AlertItem.

3. Biến global emergencyPackages ❌

Tại Models.swift:112-117, mảng emergencyPackages nằm ở top-level scope (không thuộc class/struct nào). Nên đặt vào MockData hoặc tạo struct riêng.

🟡 Vấn đề cần cải thiện

4. Hardcoded data ở RescueView & HomeViewModel

  • RescueView.swift — Toàn bộ data (rescue requests, resource numbers) đều hardcoded ngay trong View, không có ViewModel
  • HomeViewModel.swift — Dùng MockData.alerts trực tiếp, currentRiskLevel cũng hardcoded .severe

5. Business logic trong View

  • HomeView.swift:54-59: Gọi Auth.auth().signOut() trực tiếp trong View thay vì delegate cho ViewModel
  • SafetyView.swift:198-203: Hàm sendSMS() nằm trong View, nên chuyển ra service/ViewModel

6. Trùng lặp UI code — Logo Header

5/5 tab views có đoạn code logo giống hệt nhau:

// Xuất hiện ở: HomeView, ReportView, SafetyView, RescueView
Image("AquaLogoHeader")
    .resizable()
    .scaledToFit()
    .frame(height: 100)
    .padding(.top, -20)
    .frame(maxWidth: .infinity, alignment: .center)

Nên tạo một LogoHeaderView component dùng chung.

7. Severity color logic bị trùng

Logic mapping SeverityLevel → Color xuất hiện ở 2 chỗ:

  • Models.swift:16-23 — SeverityLevel.color
  • HomeView.swift:228-235 — StatusCard.backgroundColor

Cả hai đều mapping severity → color, nhưng StatusCard tạo riêng computed property thay vì dùng level.color sẵn có.

8. Thiếu Error handling & Loading states

  • MapViewModel.fetchFloodZones() chỉ print() lỗi mà không hiển thị lên UI
  • MapViewModel.getDirections() không có loading indicator
  • AuthenticationViewModel không có async/await — dùng callback lồng nhau

💡 Nhận xét chung Nhìn chung, dự án có nền tảng tốt cho một MVP. Pattern MVVM được áp dụng đúng hướng, UI components được tách rõ ràng.
